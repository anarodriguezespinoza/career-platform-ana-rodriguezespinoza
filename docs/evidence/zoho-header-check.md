## Analysis

| Field | Value | What it shows |
| --- | --- | --- |
| `Message-ID` | `<1a157362628.…@anarodriguezespinoza.com>` | The ID was generated by the sending system under the custom domain. Zoho names messages after the sender's domain, not `zoho.com` |
| `From` | `ana@anarodriguezespinoza.com` | The visible sender is the custom address, not Gmail or a zoho.com address |
| "Using Zoho Mail" | Zoho Mail | Gmail read the mailer header (`X-Mailer`/`User-Agent`): the message was composed and sent by Zoho, the managed provider, not by my laptop or the web server |
| Delivery time | created 19:48, delivered after 4 seconds | One direct hop from Zoho's outbound server to Gmail's MX, with no queueing or retries. Compare "Test 00", which waited 68 minutes because no MX existed yet |
| SPF | `PASS with IP 165.173.180.52` | Gmail took the IP that connected to it (Zoho's outbound server) and checked it against `v=spf1 include:zohomail.com ~all`. The IP is inside Zoho's published ranges, so the domain authorizes it to send |
| DKIM | `PASS with domain anarodriguezespinoza.com` | The message carried a DKIM signature with `d=anarodriguezespinoza.com`. Gmail fetched the public key from DNS (selector `zmail`, record `zmail._domainkey.anarodriguezespinoza.com`) and the signature verified, so the signed headers and body weren't changed after Zoho signed them |
| DMARC | `PASS` | DMARC needs SPF or DKIM to pass **with a domain that matches `From:`**. DKIM's `d=` is exactly `anarodriguezespinoza.com`, the `From:` domain, so DMARC passes on DKIM alone, whatever envelope sender SPF checked. With `p=none` a failure would still have been delivered, but it would have shown up in the aggregate reports |

## Conclusion

The reply left through Zoho's servers, came from the custom address, and passed all three checks. DKIM with an aligned domain is the strongest of them: it would still pass if the message were relayed, while SPF can break when the connecting IP changes. That's why the DMARC result rests on it.
